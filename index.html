#2Developing a Research Agenda

  • #research
  • #paper-reading
  • #literature
  • #learning
  • #collaboration
  • Keep a written list of open questions, including ideas beyond your current work.
  • Use those questions to guide paper searches, research digests, and a small set of journals.
  • Try to read a paper each week: start with the introduction and results, then dig into proofs or experiments when useful.
  • Follow useful older papers through the later work that cites them.
  • Review and record what you have learned regularly; spaced-repetition tools can help retain the main points.
  • Share ideas, collaborate, and learn from people with complementary skills.

#4Project Planning & Delivery

  • #project-management
  • #project-planning
  • #research
  • #requirements
  • #feasibility
  • #risk-management

A flexible sequence: research and formal documentation depend on the project, and risks and measures should be revisited as work progresses.

  • Initiate: Frame the problem and context, identify stakeholders, and set the aim, objectives, and desired outcomes.
  • Research, when relevant: Develop research questions, review relevant literature, and conduct research and analysis. For other projects, investigate the domain or technical context as needed.
  • Define requirements and scope: Analyze stakeholder needs; set the scope, deliverables, acceptance criteria, assumptions, constraints, and limitations. Write a Statement of Work (SOW) when a formal agreement is needed.
  • Assess feasibility and risk: Analyze technical, financial, and operational viability; consider legal, schedule, environmental, and social factors where relevant. Record risks and mitigations.
  • Plan delivery: Create a Project Management Plan covering milestones, schedule, budget, resources, roles, communication, quality, change control, and ongoing risk management. Define performance indicators (KPIs), baselines, and targets.
  • Develop and validate: Build the solution and check it against the requirements and acceptance criteria.
  • Measure and adapt: Track KPIs, review outcomes, and adjust the plan as needed.

#5Web3 Development Toolkit & Workflow

  • #web3
  • #solidity
  • #foundry
  • #testing
  • #dapp

A Web3 app involves more than smart contracts: the backend, frontend, wallet connection, and on-chain data need to work together. A local chain makes it possible to test the full flow before deploying to a public network.

  • Contracts and local testing: Solidity with Foundry: Forge builds and tests contracts, Anvil runs a local chain, and Cast interacts with contracts from the command line.
  • Backend and frontend: Use the stack that fits the app. viem handles TypeScript interactions with EVM chains; for React, wagmi provides hooks and RainbowKit adds wallet-connection UI.
  • On-chain data: Ponder or The Graph can index contract events and make that data available to the app.
  • Simulation and debugging: Tenderly can simulate transactions, help debug execution, and support fork-based testing.
  1. Define user flows and expected results, such as depositing, purchasing, or lending.
  2. Write the smart contracts and test them with Forge.
  3. Start Anvil and deploy the contracts locally.
  4. Write Bash scripts that use Cast commands to repeat end-to-end scenarios, including failure cases.
  5. Connect the backend, frontend, and indexer to the local contracts and test the complete flow.
  6. Test on a testnet or fork, fix issues, and review security.
  7. Deploy to the target network, verify the contracts, set up monitoring, and launch.

AI can help draft the Bash scripts and connect the pieces into end-to-end scenarios. Run the flows locally and check their results before relying on them.
